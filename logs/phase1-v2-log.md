### Split manifest done (2026-11-02)
What it does: it decides, before any model is trained, which circuits, neurons, kinds of
poke and brain states are kept back for testing, and which are used for validation. A trial
counts as test data if any one of its four units is held back. The decision depends only on
unit names and one seed, never on a trial's own noise seed, so repeats of the same trial
can't end up on both sides. The manifest is saved as JSON with sorted keys, so the same
split always gives the same bytes and the same hash.

- Tests (7B): `tests/test_m1_splits_manifest.py` (8 tests: same seed gives same split, input
  order doesn't matter, each kind is a clean three-way split, sizes, neuron splits only for
  training circuits, too few units fails, file round trip) and `tests/test_m1_splits_trials.py`
  (4 tests: how a trial is sorted, seeds don't matter, which kinds a trial is held out on,

## 2026-11-02 M3: planted circuits

### Two building blocks: a circuit writer and a batched runner
Every M3 circuit is graded (no spikes), so two pieces are needed before any switch:

- **`nexus/circuits/graded.py`** turns a circuit description (neurons, graded synapses, gap
  junctions) into NeuroML and LEMS files. Each neuron is a passive cell that can't fire. The
  7B's first version had two bugs (a stray period, and `xmlns_xsi` instead of `xmlns:xsi`);
  one edit fixed both. Check: rebuilding the M1 graded reference circuit from a description
  gives the same NEURON voltages to within 1e-6 mV, and Jaxley matches NEURON within 0.02 mV
  (6 tests, `tests/test_m3_writer.py`).
- **`nexus/circuits/batch.py`** builds a circuit in Jaxley once and runs many trials of it
  together on the GPU. Pokes, the brain-state drive and noise all enter as injected-current
  arrays, so each circuit compiles once however many trials it has. It matches an ordinary
  Jaxley run within 0.001 mV, and trials in one batch don't affect each other (5 tests,
  `tests/test_m3_batch.py`).

One director mistake: the first runner test assumed every cell rests at -70 mV. A graded
synapse is partly open at rest (about 12% here), so the cell it feeds rests near -66.1 mV.
The runner was right; the test was fixed to expect the true resting value.

### Motif tables and the circuit builder
- **`configs/motifs/`** holds one JSON table per circuit kind: the four switch types that
  can be built now (release, gain, winner-take-all, global shutoff), two decoys (adaptation,
  shunting inhibition) and plain circuits. A table lists the core neurons, the synapses
  between them with weight ranges, where the brain-state neuron connects, and which input
  pairs to probe. `common.json` holds the shared ranges (capacitance, leak, synapse
  midpoints, 2 to 15 background neurons, 6 brain states from 0 to 30 mV). The 7B garbled
  a single all-motifs file (it dropped both decoys); one file per motif fixed that.
- **`nexus/circuits/build.py`** samples one circuit from a table. Synapse weights are in
  units of the receiving cell's leak, and drives are in mV of steady-state depolarisation,
  so multiplying every capacitance and conductance by the same factor gives a degenerate
  twin with identical voltages. Background neurons only listen to the motif, never feed it,
  so they can't create or break a switch; gap junctions join background neurons only. One
  7B bug (range overrides ignored) was fixed by an edit. 35 tests, including the twin check
  (voltages within 1e-3 mV).
- **`nexus/circuits/measure.py`**: small measurement functions (window means, threshold
  crossing, 63% times, gate ratios, the switch/none/ambiguous rule, priority ranks).
  11 tests.

### Measuring the planted answers: the probe
The planted datasheet is measured, not assumed, by a fixed protocol in
`nexus/circuits/probe.py` (brain state 0):
- **Trigger and threshold.** The trigger is held at 13 levels from 0 to 30 mV; at each, a
  15 mV, 100 ms pulse goes into the test input. The response is the output's mean voltage
  over the last 50 ms of the pulse, minus the same window in a matching run without the
  pulse. Trigger gain is the response at 30 mV over the response at 0. Threshold is the
  trigger level where the response is halfway between the two.
- **Timing.** The test input is held on, the trigger switched on at 1500 ms and off at
  3200 ms; on and off times are the 63% times, divided by the median membrane time constant
  of the neurons the switch reaches.
- **Reach.** The share of non-input neurons whose pulse response changes by more than 1 mV
  when the trigger goes from 0 to 30 mV.
- **Priority.** With every trigger on, the gate whose response changes most ranks first.
- **Accepted** circuits: every gate changes its response at least 2-fold, with all timing
  and threshold values defined. A no-switch or decoy circuit is accepted only if no probed
  pair changes by more than 1.5-fold. Anything in between is rejected as ambiguous, so the
  library has no borderline cases.

The 7B's first version had a non-code line where a docstring belonged, never collected the
gate ratios, and merged the two acceptance rules; one edit fixed all of it. The tests check
the direction of each switch (release and gain raise the response, shutoff lowers it),
that shunting inhibition never raises it, that winner-take-all gets two ranked gates, and
that a twin gets the same datasheet within 0.1%.

One gain circuit (seed 1) went the wrong way: ratio 0.28. Cause, from the motif numbers:
the trigger synapse onto the gain neuron was strong enough to push it past the steep part
of the output synapse into saturation, so the test pulse had less room, not more. The
design was wrong, not the code. Weights changed: test input to gain neuron 0.05 to 0.15
(was 0.3 to 0.6), trigger to gain neuron 0.25 to 0.45 (was 0.5 to 1.0), which puts the
gain neuron near the output synapse's midpoint at full trigger. 45 tests pass on the rig
(probe and builder), about 20 s per circuit including compilation.

### The trial protocol
`nexus/perturb/protocol.py`. Decisions (mine):
- **One trial** is 2000 ms at 0.2 ms steps. The brain-state drive on neuron S is held from
  the start at one of 6 levels (0, 6, 12, 18, 24, 30 mV). The poke starts at 1500 ms, after
  the circuit has settled. Voltages are kept from 1400 to 2000 ms at 1 ms.
- **Pokes:** 5 types (5 mV for 100 ms, 15 mV for 100 ms, -15 mV for 100 ms, 30 mV for 20 ms,
  10 mV for 300 ms), each on the same 10 sampled neurons, so 50 pokes. Using the same
  targets for every type means a held-out poke type is new as a poke, not as a target.
- **Noise:** independent Gaussian current noise on every neuron at every step, sized as
  10 mV of steady drive per step (about 0.1 to 1.4 mV of voltage noise, depending on the
  cell's time constant). Drawn in advance from the circuit seed, state, seed index and poke.
- 50 pokes x 6 states x 3 seeds = 900 trials per animal. Batches are padded to one size so
  each circuit compiles once. 6 tests.

### Wiring corruption
`nexus/circuits/corrupt.py`. The model is given an imperfect wiring diagram; the simulated
circuit is never changed. Each edge can be missing, have its sign flipped, or get a weight
error (log-normal), and false edges are added. Weights are in units of the receiving cell's
leak, so a twin gets the same diagram. **The rates in `configs/corruption.json` (10% missing,
5% false, 5% sign flips, weight error sd 0.3 in log units) are placeholders, flagged
`"provisional": true` in the file.** They aren't from a measured comparison of connectomes.
They need sourced values, and a new pre-registration version, before the library is
generated. 7 tests.

### Run files
`nexus/circuits/write_run.py` writes one animal (one circuit, one corruption draw, 900
trials) as one NWB file: run metadata, the planted answers, the corruption rows, a trials
table, the pokes, the voltages (gzip), the true circuit, the corrupted diagram and the
simulator inputs. **Simulator inputs:** storing every trial's full current array would be
about 0.7 GB per animal, so the file stores the parameters that generate them and a SHA-256
of each trial's exact array, taken at the moment it goes to the simulator. A test
regenerates the arrays from the stored parameters and checks the hashes match. That is the
check the pre-registration asks for (section 6), done by hash. The file passes the M1
checker, with Cost blank as section 8 allows. Two fixes: NWB can't store 0-d arrays (the
7B's writer was fixed to use one-element arrays), and my test compared hashes with `str()`
when HDF5 returns bytes (the test was fixed). 5 tests.

### Acceptance survey and one motif fix
8 circuits per motif through the probe (`scripts/m3_acceptance.py`): release 7/8, gain 8/8,
winner-take-all 7/8, global shutoff 8/8, both decoys 8/8, plain 1/8. Plain circuits failed
because a second excitatory input onto the same cell halves the first input's response
(less driving force, more conductance). That's real biophysics, but it makes a plain
circuit look like a switch. Fix: the second input now drives its own output and makes only
a weak connection (0.05 to 0.15) onto the first output. After the change, plain circuits
pass 8 of 8 (ratios 0.79 to 0.93).

### A known weakness: twins
Degenerate twins are made by scaling every capacitance and conductance by one factor. The
voltages and the leak-relative wiring are then identical, so a twin is indistinguishable
from its original to any model that reads voltages and the diagram. The twin test
(pre-registration 5.4) would pass trivially. Twins that differ in a way a model can see,
yet have the same datasheet, need a search over parameters. That's not built yet and is
listed as open.

## 2026-11-03 M4: scoring, locked before any training

### The scoring code
Written before any model exists, as section 2 of the pre-registration requires. Three
modules in `nexus/score/`, 26 tests, all passing on the rig.
- **`recovery.py`** (sections 5.1 to 5.4). A field is recovered when its 90% interval
  contains the planted value and is no wider than half the prior range. A circuit is
  recovered when a switch is called, every planted gate is found (matched by trigger),
  every identifiable field is recovered, and **every pair of gates is in the right priority
  order** (my reading of "pairwise order agreement": with two gates there is one pair, so
  anything short of full agreement is a miss). Also: no-false-switch, twin match (both
  recovered and intervals overlap on every identifiable field), and an interval score.
  The pre-registration says "an interval score (CRPS)"; CRPS needs a full distribution, so
  what's implemented is the standard interval score for a 90% interval, and it's named
  that.
- **`prediction.py`** (sections 5.6 and 5.7). The noise ceiling is the square root of the
  split-half reliability after Spearman-Brown correction: the highest correlation a
  perfect model could reach against the seed-averaged response. A model's score is its
  correlation divided by that ceiling. The paired bootstrap resamples circuits and, for
  each, one of its 100 split-half ceiling values, so ceiling uncertainty is carried into
  the interval. A test checks the ceiling against theory: signal and noise of equal
  variance with 10 seeds gives 0.953, as it should.
- **`report.py`** turns predictions into the result table: recovery per switch type with
  the prior-only null row, no false switches overall, for plain circuits and for each
  decoy kind, twins, interval coverage per field, and prediction against baseline 1
  (pooled and per state) with the 0.1 ceiling floor and the tie rule against baseline 4.
  "State-dependent nudges" is defined in code as the part of each poke response that
  differs between brain states (the response minus its mean over states).

### Scoring scales (my decision)
Planted trigger gains run from 0.005 to 2243 over the first 47 accepted gates, and the
timing ratios from about 2 to 36. On a linear scale almost any interval would count as
narrow. Gains and both timing ratios are scored in log10; threshold and reach stay
linear. Prior ranges (`configs/scoring_priors.json`): log10 gain -3 to 4, threshold 0 to
30 mV (the trigger range used by the probe), log10 timing ratios -1 to 2, reach 0 to 1.
Under the pre-registered half-range rule, a gain interval can still span 3.5 decades and
pass. That is loose. The prior-only null row is the guard against a test this loose, and
it's reported either way.

### Pilot stopped and protocol fixed: paired pokes
While designing the recovery model I found a gap in the trial protocol. Trigger gain is
defined as the test pathway's response with the trigger held on versus off. The protocol
only had single brief pokes, so the trigger was never held while the test input was
poked. Trigger gain was visible only indirectly, through the brain-state neuron, and the
identifiability step would probably have marked it "not identifiable" because the data
never showed it (the pre-registration's own failure case, section 9).

Fix: a sixth poke type, **paired**. One input is held at 30 mV for the whole trial while
another input gets a 15 mV, 100 ms poke, the same measurement the probe uses. 10 paired
pokes per animal, sampled from ordered pairs of input neurons (the experimenter knows
which neurons are inputs). An animal now has 60 pokes and 1,080 trials, 20% more than
before. The pre-registration says "about 50 pokes"; 60 goes into the next version, along
with the sourced corruption rates and the library size.

The pilot was stopped after 27 circuits (all accepted on the first try; 32 to 102 s and
12 to 32 MB each) and restarted on the new protocol. The 27 old files are kept on the rig
in `outputs/m3_pilot_v1_unpaired/` as a timing reference only. The baselines fit a
separate gain for paired pokes, and the trials table records the held neuron. The 7B's
first test update silently dropped two existing checks (no poke on S, every target is a
real neuron); a correction restored them. Full suite on the rig: 231 passed, 2 skipped
(network), 2 expected failures (the known translator issue).

### Baselines
`nexus/baselines/wiring.py` and `linear.py` (11 tests). One linear-response family:
edges become a signed matrix (gap junctions both ways), each row is divided by one plus
its total weight, and the response to a poke on neuron j is a fitted gain per poke type
times column j of inv(I - alpha W). Alpha comes from a grid and the gains from least
squares, fitted across training circuits. Baseline 1 uses the corrupted diagram, pooled
over states or fitted per state (an unseen state uses the nearest fitted one). Baseline 4
adds a gain that changes linearly with the state drive. The other baselines swap the
matrix: one synapse step, none (wiring-blind), all-to-all, or a shuffled diagram. A pooled
model makes the same prediction in every state, so its state-dependent part is zero and
its correlation is undefined; it will be scored as 0. That's a scoring rule for the
prediction-row builder, which isn't written yet.
Second fix a minute into the restarted pilot (stopped again, nothing kept): a paired
poke needs an unpaired reference, the same 15 mV, 100 ms poke on the same target with
nothing held. That's the existing 15 mV poke type, but only when the input happened to be
sampled as a target. Now every input neuron is always one of the 10 targets, and the rest
are filled at random. No extra trials. New test: inputs are targets for every poke type.
Third and last protocol change before the pilot (stopped again, nothing kept). Working
through what each planted field needs, two were still unmeasurable:
- **Threshold** is the trigger level where the gate is halfway open, but paired pokes
  held the trigger only at 30 mV. Paired pokes now hold at 10, 20 or 30 mV, covering each
  ordered input pair and level before repeating any.
- **Timing** is measured with the test input held while the trigger steps on and off. No
  trial did that. New poke type **paired step**: one input held at 15 mV for the whole
  trial, another stepped to 30 mV from 1500 to 1800 ms. Pairs are ordered, so each input
  is held in some steps and stepped in others.

An animal now has 70 pokes (50 single, 10 paired, 10 paired steps) and 1,260 trials, 40%
more than the original 900. Tests updated (not frozen ones); full suite on the rig: 233
passed, 2 skipped, 2 expected failures. The off-time window is 200 ms (1800 to 2000 ms),
which is short for the slowest cells (time constants up to 500 ms). Whether off-time is
recoverable is for the identifiability step to say.
Fourth change, again before any pilot data was kept: sampling 10 paired pokes would often
miss the one input pair that matters in winner-take-all (4 inputs, 12 ordered pairs, 36
pair-and-level combinations). Paired pokes now cover every ordered input pair at every
hold level, and paired steps every ordered pair, with no sampling. A two-input circuit
gets 6 paired pokes and 2 steps (58 pokes, 1,044 trials); winner-take-all gets 36 and 12
(98 pokes, 1,764 trials). New test: every pair and level is covered for winner-take-all.
The 7B twice dropped existing test lines when rewriting the whole test file; the third
attempt had it write only the changed functions, which were then joined with the
unchanged ones (the split CLAUDE.md suggests for long files). Full suite: 234 passed,
2 skipped, 2 expected failures.

### Dusk recovery, version 0
Two files, both written by the 7B.

`nexus/models/summary.py` turns one animal's measured voltages into 12 numbers per
candidate trigger (each input neuron): how much holding that input changes the response
to a poke on another input at 10, 20 and 30 mV, the half-way hold level, on and off times
from the paired steps, the cell's own time constant, how many neurons move, and how much
the response changes across brain states. Each number has a "missing" flag, giving 24
features. Only voltages go in; the planted answers are never read here.

`nexus/models/dusk.py` is a small network (24 inputs, two layers of 128, 11 outputs)
trained across circuits. For each candidate it gives a switch probability and a 5% and
95% value for each continuous field on the scoring scale, which become the interval.
Priority is the rank by size of the predicted gain. The loss is cross-entropy for the
switch call plus a quantile loss for the intervals, counted only where a switch exists.

4 tests: scale conversions, the output format, array shapes, and that a model trained on
one release circuit and one shunting decoy calls both correctly. That last test only
shows the code can learn; it says nothing about circuits it hasn't seen. Two tests in
the summary file check features on a release circuit and a decoy. All pass on the rig.

This is a first version to get the full pipeline running end to end on the pilot. It
treats each candidate separately, so it can't use the wiring diagram yet.

### Prediction rows, cache and pilot evaluation script
All written by the 7B.

- `nexus/models/rows.py` builds one scoring row per animal. It takes each model's
  predicted responses, keeps only the part that changes with brain state, and correlates
  it with the measured state-dependent part averaged over noise seeds. It also gives the
  split-half noise ceiling from the seeds. The brain-state neuron itself is left out,
  since its response is set by the state drive. A model whose prediction doesn't change
  with state scores 0, as decided earlier. 6 tests.
- `scripts/m4_cache.py` reduces each accepted animal to what training and scoring need:
  the Dusk feature rows, the poke responses for every seed, the pokes, the corrupted
  diagram and the planted answers. That is about 80 KB per animal against 25 to 50 MB
  for the run file, so the full library fits in memory. Dusk and the rows builder use the
  cached values when an animal carries them (a two-line change to each, by the 7B).
- `scripts/m4_pilot_eval.py` splits the pilot by circuit (60% train, 20% validation,
  20% test), fits the seven linear baselines and Dusk recovery on train, and scores on
  validation only. The pilot's test part is never opened, so it stays available as a
  second check. Every continuous field counts as identifiable for now, until the
  identifiability step says which are.

A smoke run on the first 14 animals worked end to end (3 validation animals, so the
numbers mean nothing yet). The median noise ceiling was 0.92 with 3 seeds.

Gap against the pre-registration: it asks for at least 10 noise seeds per circuit for the
ceiling, and the protocol has 3. That's fine for development, but held-out circuits will
need 10. To go in the pre-registration revision.

### Dusk response model, version 0
`nexus/models/response.py`, written by the 7B (one correction pass to add docstrings,
checked to change no code line). It predicts every neuron's response to every poke under
every state, from the stored (corrupted) diagram. Each neuron gets 8 numbers: poke size
and length if it is the target, hold level if it is held, whether it is the state neuron
or an input, and the state level. Four rounds of message passing follow, one sum per edge
kind (excitatory, inhibitory, shunting, gap junction) plus that sum times the neuron's own
state, so a held input can scale the effect of another. It is trained across circuits on
seed-averaged responses, with the part that changes across states counted twice in the
loss, since that part is what's scored. Poke size, length and state level are numbers,
not labels, so it can be asked about held-out poke types and states, which the
pre-registration requires. 4 tests, including that it learns a gain that rises with state.

It doesn't use the recovered datasheets yet. Whether adding them helps is the comparison
that tests the switch view directly; that is version 1.

The evaluation script now runs the pre-registered prediction test on validation: Dusk
against baseline 1 pooled and per state, and the tie rule against baseline 4.

### A flaw in the locked scoring code
The smoke run gave an undefined lower bound for the bootstrap. Cause: one shunting decoy
had a mean noise ceiling of 0.125, just above the 0.1 floor, so it is kept, but 28 of its
100 split-half samples were exactly 0. The bootstrap divides each circuit's score by a
sampled ceiling, so a zero gives infinity. Ten seeds, as the pre-registration requires,
make this rarer but not impossible. The locked code is not changed. Proposed fix for the
next scoring lock, for Udeern to approve: floor each ceiling sample at 0.1, the floor the
pre-registration already applies to whole circuits.

### Which fields can be recovered: the identifiability step
`nexus/models/identifiability.py`, written by the 7B (two corrections: it first computed
the always-defined fields per animal instead of over all of them, and subtracted a set
from a list). This is pre-registration section 5.2. For each switch type, sbi's neural
posterior estimator (NPE, a masked autoregressive flow) learns the planted field values
from the summary features of training circuits, with the scoring priors as a uniform box.
Each circuit's 90% interval comes from a model trained without it (5 folds), so the
widths aren't flattered by fitting. A field counts as identifiable for a type when that
interval is at most half the prior range in at least 80% of the type's circuits.

The pre-registration asks for "perfect" training data. The summary features use only
voltages, and wiring corruption changes only the stored diagram, so the features already
meet that. They still carry the recording noise, which is part of the measurement.

A type with fewer than 20 planted triggers in training is marked "not decided", because
sbi can't train on so few (its batch size came out as 0 on the first smoke run). In the
pilot evaluation an undecided type is scored on every field defined for it, the strict
choice. An empty list would have let recovery pass on the trigger and priority alone. In
the pilot, with about 17 training circuits per type, most types will be undecided; the
full library settles it. 3 tests, including that an informative feature gives a narrow
interval and a pure-noise feature doesn't.

### Another flaw in the locked scoring code, and a draft revision of the pre-registration
The smoke run showed the prior-only null passing recovery for winner-take-all. Part of
that was the small sample: winner-take-all had no training circuits yet, so no fields
were checked. The real problem is in the priority check: a predicted tie counts as
agreement whenever the planted order happens to run the other way. The null ranks every
gate equal, so it passes about half of all one-pair circuits on label order alone.
Section 9 of the pre-registration counts a passing null as a failure of the plan.
Proposed fix for the next scoring lock: a tie counts as disagreement. The locked code is
not changed.

### Bistable decoy
`configs/motifs/decoy_bistable.json`, written by the 7B. Two neurons, A and B, excite
each other through synapses with a high, sharp threshold (-45 to -40 mV, width 2 to 3 mV)
and weights of 1.2 to 2 times the leak. At rest the synapses are off and the pair stays
down; once pushed up, each holds the other near -30 mV. A brief pulse into the trigger
latches the pair, and A excites the output. The input reaches the output on its own
path, so its effect adds and nothing gates it. It looks like a switch with memory but
has no gate, which is what a decoy must do.

First version: one seed in three failed to latch, because the weakest trigger weight
only pulled A to about -50 mV, below the pair's threshold. Trigger weight raised to 1 to
1.5 times the leak. Now:
- `tests/test_m3_bistable.py` (by the 7B): a 100 ms pulse leaves A more than 20 mV up two
  seconds later, and without it A stays within 2 mV of rest. Passes for 3 seeds.
- Acceptance survey: 8 of 8 accepted, input-to-output ratios 0.71 to 0.87 with the pair
  latched (the output loses some driving force), all classified "no switch".

The survey script now takes optional motif names, so one motif can be surveyed alone.
The bistable decoy isn't in the running pilot, which loaded its motifs at the start.

### The NEURON check per circuit type
The pre-registration (section 6) requires Jaxley and NEURON to agree to within 0.02 mV
on graded voltage. M1 showed that for the two reference circuits. This is the same check
for every motif: one circuit of each type, with current pulses into the state neuron and
every input so the switches operate, run 600 ms in both simulators. Test and diagnostic
script (`tests/test_m3_neuron_types.py`, `scripts/m3_neuron_diff.py`) written by the 7B.

The first run, at a 0.01 ms step, failed for 7 of 8 types, in two different ways:
- **NEURON blew up** in three types (values of 1e300 and then nan). In the bistable
  decoy it starts at about 172 ms, once the latched pair is far above its synaptic
  threshold. The NeuroML graded synapse relaxes with a time constant of
  (1 - s_inf) / k, which goes to zero when the presynaptic cell is far above a sharp
  threshold; the equation becomes stiff and NEURON's integration of it diverges at
  0.01 ms. Jaxley stayed in range throughout.
- **Small excesses** elsewhere, 0.021 to 0.030 mV, mostly in the first 2 ms.

At a 0.0025 ms step NEURON no longer diverged, but the differences grew to 0.08 mV. Fine-
step Jaxley disagreed with coarse Jaxley by exactly as much as with NEURON, which
pointed at float32: at that step each voltage update is smaller than float32 can resolve
around -47 mV, so error builds up over 240,000 steps. Rerun with JAX in float64: Jaxley
and NEURON agree to within 0.007 mV on every neuron of both types tried (release and
the bistable decoy), well inside 0.02 mV. The translation from NeuroML to Jaxley is
correct for these circuits; the earlier failures were numerical, not modelling errors.

The test now runs at 0.0025 ms and skips unless JAX runs in float64
(`JAX_ENABLE_X64=1`). Turning float64 on inside the test would change every other test
in the same session.

A separate finding from the same runs, which needs a decision: **the library's own step
is 0.2 ms**, and at that step voltages differ from the converged solution by 0.03 to
0.3 mV for most neurons and up to 0.87 mV in the latched bistable pair. The planted
answers are measured by the probe at the same step as the data, so the test bench is
consistent with itself. But the simulated circuit is "the NeuroML circuit at 0.2 ms",
not the continuous model. Options: keep 0.2 ms and say so in the pre-registration, or
halve the step (doubling simulation time). Added to the revision draft.

### Degenerate twins that actually differ
The existing twins are uniform rescalings: every capacitance and conductance times one
factor, which leaves every voltage unchanged, so a twin test on them can't fail.
The pre-registration defines twins as the same planted values with different biophysical
parameters. `nexus/circuits/twins.py` (by the 7B, one docstring pass checked to change no
code) does that: it multiplies each capacitance, leak and conductance by its own
log-normal factor (sd 0.25, so typical changes of about 25%), re-measures the copy with
the probe, and accepts it if every continuous field is within a tolerance of the
original, as a fraction of the prior range on the scoring scale, with the same triggers
and priorities. Otherwise it tries again, up to a limit. 3 tests.

Survey (`scripts/m3_twin_survey.py`, 3 circuits per switch type, up to 10 tries,
tolerance 0.1):

| Type | Twins found | Closest distance when not found |
|---|---|---|
| release | 2 of 3 | 0.167 |
| gain | 2 of 3 | 0.125 |
| global shutoff | 2 of 3 | 0.114 |
| winner-take-all | 0 of 3 | 0.111 to 0.162 |

Most finds come on the first try. Winner-take-all has four gates and a priority order,
so every field of every gate has to land inside the tolerance at once, and none did.
Two things need deciding before the library is generated, and are in the revision
draft: the tolerance (the pre-registration says "same values", which measured values
can't meet exactly), and what to do when no twin is found. Pairing only circuits that
found a twin would leave out winner-take-all entirely and favour circuits whose fields
are insensitive to their parameters. Smaller perturbations for winner-take-all are one
option.

Result in float64 at 0.0025 ms: all 8 types pass (release, gain, winner-take-all, global
shutoff, plain, and the shunting, adaptation and bistable decoys), every neuron within
0.02 mV of NEURON for the full 600 ms. 8 minutes on the rig's CPU. Command:
`JAX_ENABLE_X64=1 JAX_PLATFORMS=cpu .venv/bin/python -m pytest tests/test_m3_neuron_types.py`.
In the normal suite (float32) this test skips and says why.
